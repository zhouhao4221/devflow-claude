# v4.0.1 (2026-09-15)

> 版本范围：v4.0.0..HEAD（#77 #78）

## 升级补充（v4.0.0 迁移说明遗漏的一步）

- **项目级插件开关要改**：若项目提交进 git 的 `.claude/settings.json`（或 `.claude/settings.local.json`）里写了 `"enabledPlugins": {"req@devflow": true}`，需改为 `rd@devflow`，否则拉代码的成员仍启用只剩 `/req:help` 的过渡插件。升级到本版后执行 `/rd:migrate` 会自动检测并在确认后替换，改完请提交。

## 修复

- **fix(QUICK-004): `/rd:pr` 支持无需求编号的分支**（#77）
  - 此前分支名不含 `REQ-XXX` / `QUICK-XXX` 时，创建流程直接提示「请指定需求编号」退出——`/rd:do` 结束后建议执行的 `/rd:pr`、`/rd:commit` 未命中需求时自动生成的分支、手工文档修复分支都走不通
  - 现在仅在 `mainBranch` / `developBranch` 上提示退出，其余分支进入「无需求模式」：标题取唯一提交标题（多提交时按分支前缀生成 `<type>: <slug>`），Body 为提交清单 + 变更统计，分支含 `-iN` 时追加 `closes #N`
  - `/rd:fix --auto` 与带需求编号的分支行为不变
- **fix(QUICK-005): 迁移补项目级插件开关检查，PR 成功提示覆盖 GitHub**（#78）
  - `/rd:migrate` 新增 2D：检测 `.claude/settings.json(.local)` 中 `enabledPlugins` 的 `req@devflow`，确认后改为 `rd@devflow`、值不变；两键并存时只删旧键；无该键时静默跳过
  - `/rd:pr` 步骤 6 的成功输出从 gitea 小节提为 gitea / github 共用：GitHub 仓库创建或复用 PR 后同样提示下一步 `/rd:pr review`；`gh` 不可用只给 compare 链接时也附该提示
  - 教程中英韩 1.6「req → rd」小节补项目级 `enabledPlugins` 提醒
