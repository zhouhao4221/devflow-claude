# v2.31.0

**发布日期**: 2026-05-12

## 新特性 (Features)

### QA 插件 - 测试流程可执行性提升

- **选择器支持**: 流程文档步骤现支持 `data-testid` 选择器（优先级：data-testid > aria-label > CSS），执行时优先从容器内查找元素，避免全页 DOM 扫描
- **等待信号机制**: 替代固定 sleep，支持文字出现/元素出现-消失/URL 变化等事件驱动等待，超时可配（默认 10-15s）
- **API-then-verify 模式**: 新增操作方式 `api-then-verify`，支持通过 API 造测试数据、再通过浏览器验证展示
- **已知结论跳过**: 流程文档新增 `已知结论` 区块，可标记已验证/不通过/无需重复验证的场景，执行时自动 SKIP
- **全局测试数据**: 流程文档新增 `测试数据` 区块，复用的账号/密码/字段值，场景中直接引用，无需重复说明
- **数据准备字段**: 每个场景支持 `数据准备` 说明（API 调用/脚本/手动），执行前自动准备或提示用户
- **data-testid 命名约定**: `/qa:init` 新增 `testid-convention.md` 生成，供前端开发参考（customer-name-input、customer-submit-button 等）

### REQ 插件

- feat(req): 需求 branch 字段支持多分支（逗号分隔）

## 升级指南

### 前端团队行动项

1. **添加 data-testid** 属性到关键交互元素
   - 参考 `docs/qa/testid-convention.md`（`/qa:init` 自动生成）
   - 优先：输入框、按钮、表格、弹窗等
   - 命名约定：`<功能域>-<元素类型>`（customer-name-input、customer-submit-button）

### 测试人员行动项

1. **更新 flow 文档** 格式（兼容旧格式，建议升级）
   - 使用新增的 `数据准备`、`等待信号`、`已知结论` 字段
   - 提升流程的机器可执行性和稳定性

2. **/qa:new** 创建新流程时，会引导填写：
   - 全局测试数据表格
   - 已知结论列表
   - 关键元素的 data-testid（不知道填"待补充"）
   - 每步的等待信号

### 执行优化

- 支持 `api-then-verify` 模式：用 API 创建测试数据，再用浏览器验证，大幅缩短测试时间
- 使用事件信号代替 sleep，提升可靠性和执行速度
