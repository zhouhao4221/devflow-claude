# v2.39.1 (2026-08-25)

> 版本范围：v2.39.0..HEAD

## 修复

- **fix(req): hook 与 skill 改读 `.devflow` 配置，修复需求上下文注入与文档校验静默失效**
  - v2.35.0（`c54eb55`）把 DevFlow 配置从 `.claude/` 迁到 `.devflow/`、移除 `~/.claude-requirements/` 全局缓存时，`hooks/` 与 `test-guide` skill 没跟着改，运行时读的仍是 v2.x 路径——两个 hook 都不报错、只是静默失效
  - `session-context.sh`（SessionStart）只读 `.claude/settings.local.json`，在任何按 v3 约定配置的仓库里都读不到 `requirementProject`，直接走进「当前仓库尚未初始化」分支 `exit 0`，需求上下文注入整体失效；同时写死 `docs/requirements` 忽略 `requirementsDir`，readonly 回退到已删除的全局缓存而非 `requirementSource.path`
  - `validate-requirement.sh`（PostToolUse）门禁写死 `[[ "$FILE_PATH" =~ docs/requirements/ ]]`，配了自定义 `requirementsDir` 的项目从未触发过章节校验
  - `skills/test-guide/SKILL.md` 仍指示 readonly 仓库从 `~/.claude-requirements/projects/<p>/specs/` 读领域规约
  - 三处统一按 `_storage.md` 的合并顺序读 `.devflow/settings.json` + `settings.local.json`；`requirementsDir` 可配置；readonly 经 `requirementSource.path` 直读主仓，目录名以主仓自身的 `requirementsDir` 为准
  - 新增两条诊断输出：检测到 `.claude/` 仍有 DevFlow 字段时提示 `/req:migrate`（`_storage.md` 已承诺、此前未实现），readonly 未绑定主仓时提示 `/req:use`；无 `python3` 时静默退出，不再谎报「尚未初始化」
  - 顺带修正 `模块` 字段提取：原贪婪正则 `s/.*[:：|]//` 会吃到表格行尾的 `|`，对真实文档 `| 模块 | xxx |` 恒返回空
  - 验证：primary / 全新仓库 / `.claude` 旧配置残留 / 自定义 `requirementsDir` / readonly 直读主仓 / readonly 未绑定 六场景实测通过；`check-layout.py --check` 通过
