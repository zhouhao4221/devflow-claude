# v4.0.0 (2026-09-15)

> 版本范围：v3.0.0..HEAD（#74 #75 #76）

## 破坏性变更（升级前先读）

- **req 插件更名为 rd**（REQ-004 #74）：命令前缀 `/req:xxx` → `/rd:xxx`，入口 `/req` → `/rd:req`，安装名 `req@devflow` → `rd@devflow`。迁移三步：
  1. `claude plugins uninstall req@devflow`
  2. `claude plugins install rd@devflow`
  3. 在已有项目中执行 `/rd:migrate`，逐处替换 `CLAUDE.md`、`docs/prompt/`、需求模板、`.claude/skills/` 中残留的旧前缀
  - 无需改动：`.devflow/` 配置、需求文档（`REQ-XXX`）、`.claude/.req-*` 本地开关
  - 更新 marketplace 后 `req` 只剩过渡插件 `/req:help`（输出上述迁移说明），v5 删除
- **`/rd:review-pr` 移除，并入 `/rd:pr` 子命令**（REQ-005 #75）：`review-pr review` / `merge` / `fetch-comments` → `/rd:pr review` / `merge` / `comments`，单独的 `review-pr` → `/rd:pr status`；`/rd:migrate` 会映射这些旧写法
- **`/rd:pr` 无参数语义变化**：原 `review-pr` 无参数为查看状态；现 `/rd:pr` 无参数为**创建 PR**（当前分支已有 open PR 时复用，不重复创建）

## 新功能

- **feat(rd)!: req 插件更名为 rd（R&D 研发）**（REQ-004 #74）
  - req 的 34 条命令中约 29 条是研发侧或通用能力（dev / do / fix / test / commit / pr / branch / issue / release 等），插件名只覆盖「需求」一块；Claude Code 插件命令前缀强制且无别名机制，更名是唯一解，与 pm（项目管理）形成分工
  - 只换前缀：命令名、`REQ-XXX` 编号、`docs/requirements/`、`requirement*` 配置字段、`.req-*` marker 均不变，老用户 `.devflow/` 零迁移
  - 过渡插件 req 5.0.0；`/rd:migrate` 新增 2C 命令前缀迁移，逐处 `y / n / a / q` 确认并汇总
- **feat(rd)!: PR 命令合并为 `/rd:pr` 子命令**（REQ-005 #75）
  - `/rd:pr [status|review|comments|merge]`，与 `branch` / `issue` 结构一致；`fetch-comments` 视同 `comments`；`--level`、`--auto`、`PR-ID` 参数保留
  - 审查 / 评论 / 合并流程细节移入 `shared/pr-ops.md`，命中子命令才读取，创建 PR 路径不加载
  - 顶层 `review` 只剩需求评审一种含义；自然语言调度器新增「看看 PR / PR 状态」→ `/rd:pr status`

## 改进

- **`check-layout.py` 过时引用规则扩展**（#74 #75）：新增 `/req` 旧前缀与 `review-pr` 两条规则，扫描范围从插件目录扩到 README / tutorial 三语、CLAUDE.md、`docs/design`、`docs/prompt`、需求索引 / 模块 / 模板；规则按条目区分是否扫描仓库文档，过渡插件目录豁免；CI 每个 PR 自动执行
- `.gitignore` 忽略 `__pycache__/`、`*.pyc`
