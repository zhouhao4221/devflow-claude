# v5.0.1 (2026-09-19)

> 版本范围：v5.0.0..HEAD（#94 #95）

## 改进

- **会话模型按非 Fable 设计，高推理命令显式 `model: best`**（#95）
  - 背景：会话默认改用 Opus 5 / Sonnet 5，Fable 5.1（$10/$50，Opus 5 的 2 倍）只在需要高度思考时调用
  - `/rd:dev`、`/rd:do`（实现方案设计）、`/rd:fix`、`/diag:diagnose`（根因分析）、`/rd:review`（代码审查）补 `model: best`：Fable 可用时解析为 Fable 5.1，不可用（组织禁用、云厂商未上架）时退到 Opus，并按 provider 解析模型 ID
  - `/rd:new`、`/rd:req-review`、`/rd:init`、`/pm:plan`、`/pm:ask` 留省略档，继承会话模型
  - 命令的 `model` 覆盖只到当轮（官方文档 2026-09-19 核实）：dev / do / fix 用 Fable 出方案，确认后的实施回到会话模型
  - 部分套餐下 Fable 按 usage credits 计费，交互会话首次会弹同意提示

## 修复

- `/rd:migrate`：裸 `/rd:review`、`/rd:review comments`、`/rd:review --auto` 不再误建议改成 `/rd:req-review`，只列出并标「需人工判断」；仅后跟 `REQ-XXX` / `QUICK-XXX` / `pass` / `reject` 时才映射（#94）
- `/rd:req-review`（#94）：
  - 评审记录表只有占位行时用首条记录替换，不再追加在占位行之后
  - 预审后用户选 n 时结论写 `预审未提审`，不再误写 `提审`
  - 带阻塞项仍提审时，评审摘要与结尾提示标出 `⚠️ 带 N 项阻塞`
  - readonly 仓库只展示预审意见，不写评审记录、不改状态
  - 预审读 QUICK 文档时只取标题与「问题描述」
  - `allowed-tools` 补 `Bash(git config:*)`（取默认评审人）；状态流转图改正为驳回后停在「评审驳回」
