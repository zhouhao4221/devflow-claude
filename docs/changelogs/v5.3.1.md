## 问题修复

示例项目实测 REQ-009 / REQ-010 发现的问题（#106）：

- **无 `architecture.md` 时层级推断错误**：`.html`、`public/` 下的文件原来被归为后端逻辑，导致 E2E 被跳过。现在补齐前端判定（`public` / `static` / `web` / `frontend` 目录，`.html` / `.svelte` / 模板）；后端逻辑只认 `lib` / `service` / `biz` / `domain` / `model` / `store` / `repository` / `dao` 目录；其余代码按「无法判定」处理，三个阶段全跑（原来的「其余代码 → 后端逻辑」让「无法判定」永远不会触发）
- **`/rd:fix` 复现探针被工作区检查拦下**：1.3.5 生成的复现探针（`acceptance/<分支 slug>/repro-*` 未跟踪文件）不再算未提交改动，建修复分支时随工作区带过去
- **探针去留**：修复停止或放弃时删除本次的复现探针；`requirement-analyzer` 的现状探针在结论写入后即删，不留在 `acceptance/` 参与回归（它断言的是需求要改掉的现状，留下必然回归失败）
