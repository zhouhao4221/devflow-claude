# v5.2.0 (2026-09-23)

> 版本范围：v5.1.1..HEAD（#101 #102）

## 新功能

- **UI 自主验收：headless 探针代替手动浏览器验证**（REQ-008，#102）
  - 背景：UI 可观察的验收项此前全靠人工开浏览器；已移除的 uat 插件在主会话里「点一步截一张」驱动浏览器，截图随历史累积，token 成本过高
  - 新增 `ui-verifier` agent（`model: inherit` · `effort: high`）：把一条验证项写成 headless Playwright 探针并运行，截图与 aria 快照只在 agent 内判读，主会话每项只收 PASS / FAIL / BLOCKED + 一句证据 + 路径
  - `/rd:test` 步骤 7「交互验证」→「自主验收」：`script` / `visual` 项并行派 `ui-verifier`，`manual` 项引导用户；报告新增「自主验收 n/m」，验收 FAIL 计入失败
  - `/rd:do`、`/rd:fix` 的手动验证清单先走自主验收，剩余才留给用户；`/rd:fix --auto` 遇 FAIL 停下
  - 前置三条：`docs/prompt/testing.md` 有 E2E 命令与前端地址、前端可达、框架为 Playwright；缺任一条退回手动并在报告写明原因
  - 回写规则：PASS 勾选并附探针路径；FAIL / BLOCKED 保持未勾（`/rd:done` 会拦下）；manual 项只有用户明确暂缓才标「未实测」
  - 探针默认保留在 `<E2E 目录>/acceptance/`，下次 `/rd:test` 阶段三当回归跑

## 改进

- `testing.md` 模板「必备输入」补 E2E 命令（headless）、前端地址、登录配方（只写 env 变量名）、产物目录、服务启动与探活；prompt-schema 1.2 对缺项只警告（#102）
