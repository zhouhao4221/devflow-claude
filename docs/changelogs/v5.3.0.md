# v5.3.0 (2026-09-24)

> 版本范围：v5.2.0..HEAD（#103 #104 #105）

## 新功能

- **测试阶段按改动层级自动选择**（REQ-009，#105）
  - `_verify.md` 新增「测试阶段选择」，作为唯一规则源：改动来源取「相对 branchFrom 的实际 diff ∪ 需求文档 11.3」；层级判定优先 `architecture.md` 分层表，缺失按路径 / 扩展名推断

    | 改动 | 阶段 |
    |------|------|
    | 仅前端 | E2E（不启动后端） |
    | 后端逻辑 / 数据访问 | UT + API（跳过 E2E） |
    | 接口层（契约变化） | UT + API + E2E |
    | 仅文档 / 配置 | 不跑 |
    | 无法判定 | 按接口层全跑 |

  - `/rd:test` 第 3 步按层级选阶段，未选中阶段不启动环境、报告写跳过原因；新增 `--all` 强制全跑；`--skip-*` 优先；`--failed` 时上次失败的阶段必跑
  - `/rd:dev` 完成提示附预计阶段与依据；`/rd:do`、`/rd:fix` 验证结果段加「建议测试」（只建议，不自动启动环境）
  - ⚠️ 行为变化：`/rd:test` 可能跳过以前会跑的阶段；需要全跑时加 `--all`
- **探针复现问题与确认现状**（REQ-010，#105）
  - `/rd:fix` 新增 1.3.5：界面可观察的问题在根因分析前先派 `ui-verifier` 复现（断言期望行为，FAIL = 已复现，期望 vs 实际交给根因分析）；无法复现时停下问用户，可重派一次，仍无法复现由用户选继续（标注「未复现」）或停止；`--auto` 无法复现即停止
  - 修复后重跑同一探针，验证结果记「复现探针：FAIL → PASS」，探针保留为回归
  - `requirement-analyzer` 第 1 轮可提议探针确认页面现状（用户同意才派），结论写入 1.1 背景并附探针路径；`/rd:new`、`/rd:edit` 引用该规则，`allowed-tools` 补 `Agent`

## 问题修复

- 自主验收实测问题（REQ-008，#103）：`ui-verifier` 的 visual 项中能用 DOM 判定的部分（禁用 / 选中 / 可见 / 文本）照样断言；账号 env 未注入 → BLOCKED；回报改相对路径；预算口径改为每个子代理新增内容 ≤ 3 万 token / ≤ $0.25；`_verify.md` 与 `testing.md` 模板写明账号 env 的注入方式
- `/rd:do`、`/rd:fix` 验证结果模板补齐 REQ-008 漏加的「自主验收」行（#105）
