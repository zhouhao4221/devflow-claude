# v4.1.0 (2026-09-16)

> 版本范围：v4.0.2..HEAD（#83 #84 #85 #86 #87）

## 升级注意（行为变更，升级前先读）

- **`/rd:new-quick` 不再一口气做到归档**：确认方案后停在「草稿」并提示 `/rd:dev`，后续与正式需求走同一组命令 `/rd:dev` → `/rd:test` → `/rd:done`，只跳过评审
- **QUICK 生命周期改四态**：草稿 → 开发中 → 测试中 → 已完成，「方案确认」不再是状态。执行 `/rd:update-template quick` 更新本地模板；存量 QUICK 文档不用手改，`/rd:test` 写状态时会自动补「测试中」复选框
- **`INDEX.md` 不再生成**：需求索引由 `/rd:req` 按目录实时渲染，已有项目可 `git rm docs/requirements/INDEX.md`
- **新增需求目录一致性守卫**：`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/check-requirements.py --check` 随插件分发，校验 `completed/` 内状态为已完成、`active/` 内不为已完成、状态与生命周期已勾格一致、编号唯一；`/rd:release` 发布前置会先跑它，建议接入 CI

## 新功能

- **feat(REQ-006): QUICK 生命周期统一命令链，索引改为实时渲染，新增需求目录一致性守卫**（#87）
  - 双轨状态机唯一定义在 `shared/_storage.md`：REQ 六态 / QUICK 四态、各状态由哪条命令写入、验证章节映射（REQ「六、测试要点」/ QUICK「验证方式」）、未勾项放行标注 `（待观察：…）` `（未实测：…）`
  - `/rd:dev`、`/rd:test`、`/rd:done`、`/rd:upgrade` 统一处理两种需求：`done` 门槛统一「测试中」、带标注未勾项放行、PRD 只跟 REQ；`dev` 对 QUICK 不生成十一章、无参自动选择纳入草稿 QUICK；`upgrade` 归档源 QUICK 时写已完成
  - `/rd:req` 与 `/rd:status` 纳入 QUICK；`/rd:req` 按七态分组、含最近 10 条已完成；`/rd:fix` 关联匹配改为扫目录
  - 原生 `/code-review high` 审查 10 条发现在合并前全部修正（含守卫的绝对路径 / readonly / 编号格式 / 单调勾选处理）
