# v5.3.3 (2026-11-12)

> 版本范围：v5.3.2..HEAD（#108、#109、#110）

## 问题修复

- **diag 风控 Hook 可被绕过（安全）**：ssh 命令识别原来只认段首恰为 `ssh` 的第一个调用，换行后接 ssh、`/usr/bin/ssh`、`command ssh`、`bash -c` / `eval` 内嵌、同一条命令里的第二个 ssh、`$(...)` / 反引号、`xargs`、非段首 `sudo`、管道给 shell 等写法会被当成非 ssh 放行，可绕过主机白名单与只读限制。现在改为失败即拦截：确定是单个 ssh 调用才继续校验，确定没有 ssh 才放行，其余一律拒绝并说明原因；`grep ssh`、`man ssh`、`ssh-keygen`、`ssh://` 等只读提及照常放行
- **diag 风控 Hook 出错时放行**：四个 PreToolUse 风控 Hook 加 `onFailure: "block"`，脚本超时、起不来或异常退出时改为拦截（需 Claude Code 2.1.295+）；缺 `jq` / `python3` 时对 ssh 命令显式拦截，不再静默放行

## 调整

- **思考型 agent effort 下调**：rd `planner`、diag `root-cause` 由 `xhigh` 改为 `high`。在 Fable 5.2 上同题实测两档质量相当，`xhigh` 的输出 token 与耗时约为 1.6–1.9 倍
- **子代理被安全机制拦下时不再由主会话接手**：`/rd:dev`、`/rd:do`、`/rd:fix`、`/rd:review`、`/diag:diagnose` 的 Fable 失败降级只覆盖额度用尽、未开通等 API 错误；被安全机制拦下时按 Claude Code 的提示缩小范围重试或告知用户（对应 Claude Code 2.1.319 的行为变化）

## 注意

- 启用 diag 后，经 ssh 执行远程命令的间接写法（`rsync -e ssh`、`git -c core.sshCommand=…`、`xargs … ssh`）会被拦截；请改为直接 `ssh <host> <只读命令>`，或在不需要诊断的会话里关闭 diag

## 其他

- 布局守卫新增检查：派 agent / 调 Skill 的命令必须在 `allowed-tools` 预授权（开了 `permissions.denyInsteadOfPrompting` 时未预授权的调用会被直接拒绝）
- 维护文档按 prompt-audit 精简模型策略，实测数据归入设计文档
