## ✨ 新功能

### qa 插件 - 浏览器 UAT/E2E 测试工作流 (REQ-002)

为 devflow 新增完整的 QA 测试工作流插件，支持测试文档管理、AI 驱动的自动化测试执行、报告生成和缺陷上报：

- **`/qa:new [module]`** - 交互式引导创建测试流程文档
  - 多轮对话收集测试场景信息
  - 自动按模板生成规范化的 flow 文档
  - 支持 browser / api / desktop 三种操作方式
  
- **`/qa:run [module]`** - 执行测试场景
  - 读取 flow 文档，调用底层工具（browser skill 等）逐场景执行
  - 记录每个场景的 pass/fail 状态和失败截图
  - 自动生成测试报告到 `docs/qa/reports/`
  - 支持灾难转移：某场景失败后继续执行后续场景
  
- **`/qa:report`** - 查看最新测试报告
  - 展示测试汇总和失败详情
  - 支持按模块查看历史报告
  
- **`/qa:bug`** - 失败项上报 Gitea issue
  - 从最近报告中读取失败场景
  - 需用户确认后创建 issue
  - 支持按 giteaToken 配置决定 Gitea 集成能力

- **`/qa:init`** - 初始化插件
  - 创建必要的目录结构（flows / reports / screenshots）
  - 安装 qa-executor skill 到项目 `.claude/skills/`，供 Codex 环境使用

### 核心设计理念

- **AI 作为指挥家** - Claude 负责编排和决策，不直接实现浏览器操作，而是调用 browser/api 等底层工具
- **文档驱动** - 测试场景沉淀为可版本管理的 Markdown 文档，知识留存
- **双环境支持** - 插件代码在项目目录，skill 文件复制到 `.claude/skills/` 供 Codex Chrome 和 Claude 桌面端使用
