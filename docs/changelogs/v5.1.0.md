# v5.1.0 (2026-09-19)

> 版本范围：v5.0.2..HEAD（#97）

## 新功能

- **「想」交给 Fable 子代理，Fable 不可用时降级到当前模型**（#97）
  - 背景：v5.0.1–v5.0.2 给思考类命令钉 `model: best`，Fable 额度用尽时命令直接报错（「You're out of usage credits…」）、整条命令锁死；`fallbackModel` 也不处理计费 / 限流错误。只有子代理失败会把错误交回主会话
  - 新增只读 agent：rd `planner`、diag `root-cause`，`model: fable`，工具只有 Read / Glob / Grep
  - `/rd:dev`、`/rd:do`、`/rd:fix`、`/rd:review`、`/diag:diagnose` 去掉 `model`，默认跑当前会话模型；只把最需要推理的一步派给 Fable：

    | 命令 | 交给 Fable 的环节 |
    |------|------------------|
    | `/rd:dev` | 步骤 4 实现方案 |
    | `/rd:do` | 步骤 2 方案 |
    | `/rd:fix` | 1.4–1.5 根因 + 修复方案 |
    | `/rd:review` | 小 PR 审查 |
    | `/diag:diagnose` | 步骤 7 根因判断 |

  - 主会话把需求要点、分层规范、`code-scout` 定位清单与返回骨架内联进 prompt，拿到结论后复核再交用户确认
  - agent 失败（额度用尽、未开通、云厂商未上架，或超轮无结论）→ 不重试，主会话用当前模型按同一骨架接手，首行标注 `⚠️ Fable 不可用，…由当前模型生成`
  - `root-cause` 不给 Bash，SSH 仍只在主会话执行，风控 Hook 与审计链不变

## 改进

- 撤回 v5.0.2 为切换模型加的限制（#97）：
  - `/rd:dev` 多个候选需求、需求有多个分支时恢复为直接选择（当前分支匹配时自动用），不再要求重跑命令
  - `/rd:do` 恢复为先问规模、再出方案
  - `/diag:diagnose` 服务对不上时恢复为列表选择（唯一匹配仍直接用）
  - 确认闸门不再要求「结束当轮」、不再排斥 Plan Mode / AskUserQuestion 的说法
