# v2.40.0 (2026-08-26)

> 版本范围：v2.39.1..HEAD

## 新功能

- **feat(req): 委派体系扩到 6 个 agent，会话模型专注判断、执行外包**
  - 起因是 dogfooding 实测：`/req:do` 开发 25 个文件全程 0 次委派，主上下文涨到 25 万后在开发中段触发压缩，已确认的方案被摘要化；`/req:review-pr` 派出的 6 个 `file-reviewer` 里 5 个撞满 `maxTurns` 交出半成品，主会话只能逐个 SendMessage 催结论，多走一趟
  - 新增 `impl-worker`（sonnet-5，含 Edit/Write/Bash，`maxTurns` 35）：按实施单修改一个独立单元。此前「写代码」这块完全没有委派承接，是最大的缺口
  - 新增 `doc-writer`（haiku，含 Write/Edit，`maxTurns` 20）：按素材 + 模板骨架成文、回填章节，不增删章节、不发明事实
  - 新增 `diff-digest`（haiku）：拉取并压缩大 diff、可逐文件落盘，diff 原文不进主会话
  - `file-reviewer` 修三个参数问题：`maxTurns` 20 → 30；受审单元从「一个文件或一组」收紧为「一个源文件 + 其测试」；新增「diff 正文已在 prompt 内，仅在无法定性时定点 Read/Grep 最多 3 处」与轮次纪律条款
  - `_delegate.md` 重写，新增四节：**分工原则**（决策层主会话 / 执行层 subagent，subagent 的结论是输入不是结果）、**委派实施准入四条**（方案确认到文件级 + 单元互不依赖 + 契约已定死 + 有验收命令，四条全满足才派）、**素材内联不给路径**、**超轮与失败处理**（SendMessage 续问而非重派，超轮过半 = 切分太粗）
  - 命令接线：`dev`/`do` 按准入条件并行派 `impl-worker`（`dev` 同层并行、跨层串行），`fix` 默认仍主会话自己改；`dev` 第 5 步方案回写、`changelog` 超 50 条提交派 `doc-writer`；`review-pr` 第 4 步拆成取 diff / 切分（每 subagent ≤1 源文件）/ 内联派发 / 汇总含超轮处理；`commit`、`pr` 大改动派 `diff-digest`
  - `changelog`、`commit`、`pr` 三条命令 `allowed-tools` 补 `Agent`
  - 验证：`check-layout.py --check` 通过（78 个菜单项无重复，89 个相对链接可达）

## 行为变化

- CLAUDE.md 原规则「不要为了省 token 把整条 `dev`/`fix` 拆成『会话模型出方案 → 其它模型执行』」改为有边界的版本：**降档不是委派的理由**——委派是为了上下文隔离（避免开发中途触发压缩、让已确认方案被摘要化），不是为了把推理换成便宜模型。写操作委派须满足准入四条，新建抽象、跨层契约变更、方案仍在演化的首版实现一律主会话自己写
- `_delegate.md` 原「subagent 只读」一条不再成立：agent 分为只读型（`code-scout`/`test-runner`/`file-reviewer`/`diff-digest`）和可写型（`impl-worker`/`doc-writer`），后者有准入门槛，验收复核的是 `git diff` 实际内容而非 subagent 的自述
