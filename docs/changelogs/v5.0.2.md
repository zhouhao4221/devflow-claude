# v5.0.2 (2026-09-19)

> 版本范围：v5.0.1..HEAD（#96）

## 修复

- **Fable 档命令的确认闸门改为结束当轮，写代码回到会话模型**（#96）
  - 背景：命令的 `model` 覆盖只到当轮，用户发下一条消息即回到会话模型。v5.0.1 的闸门位置让思考与写代码的模型正好反了：`/rd:dev` 先确认分支名、`/rd:do` 先问规模、`/diag:diagnose` 先选服务，一回复方案/分析就落到会话模型；`/rd:dev` 又用 Plan Mode 确认方案，ExitPlanMode 在同轮内返回，写代码仍跑 Fable
  - `/rd:dev`：不进 Plan Mode；分支名随方案一起展示、一起确认（可改名），确认后才建分支；多个候选需求时按当前分支名自动选，选不出请用户 `/rd:dev <编号>` 重跑；需求有多个分支且当前不在其中时，请用户切换后重跑
  - `/rd:do`：规模提示（建议改走 `/rd:new-quick` / `/rd:new`）不再单独停，并入方案末尾一起确认
  - `/diag:diagnose`：未带 `--service` 时，只有一个服务、唯一匹配或描述明确要查全部 → 直接用并在报告头注明；否则列出服务清单，请用户带 `--service` 重跑
  - `/rd:dev`、`/rd:do`、`/rd:fix`、`/rd:review comments`：展示方案后结束本轮等用户回复，不用 Plan Mode / AskUserQuestion 确认
  - `/rd:fix --auto` 无闸门，全程在命令轮内跑 Fable（小 bug 改动少，接受）
