# v2.32.0

**发布日期**: 2026-05-12

## 新特性 (Features)

### UAT 插件重构

- **插件重命名**: qa → uat（User Acceptance Testing），更准确反映功能定位——用户验收测试，而非全面的 QA
- **表单边界 & 字符类型测试**: 新增标准测试矩阵，覆盖空值、超长、最小长度、中英文混合、特殊字符、XSS、Emoji 等
  - 自动生成测试矩阵表格，逐行执行，按需裁剪
  - 流程文档新增 `SXX 表单边界 & 字符类型` 标准场景段落
- **浮层组件操作规范**: 下拉/级联选择器、DatePicker 等浮层组件的稳定操作策略
  - 触发器与浮层选项分离写法（避免在容器内查找浮层）
  - 分层等待机制（省→市→区 每层单独等待）
  - 失败重试逻辑（click 未命中后自动重试 2 次）
- **新增场景自动清理**: 测试完成后自动删除测试产生的数据（编辑场景不清理）
  - 仅限 UI 删除操作（点删除按钮、确认弹窗）
  - 无法自动清理时警告提示，不阻断报告
- **执行阶段纯 UI**: 去掉 API 调用，所有测试通过界面操作
  - 删除 `api-then-verify` 模式和 API DELETE 数据清理
  - API 信息仅在 `/uat:new` 撰写文档时作为参考（理解字段含义）
  - 数据准备改为手动准备或已有数据

## 升级指南

### 命令更新

- `/qa:xxx` → `/uat:xxx`（所有命令重命名）
- `/uat:init` - 初始化 UAT 插件，创建 `docs/uat/flows/`、`docs/uat/reports/` 等目录
- `/uat:new` - 创建测试流程，自动引导填写表单边界测试、下拉选择器规范
- `/uat:run` - 执行测试（纯 UI 操作）
- `/uat:report` - 查看报告
- `/uat:bug` - 将失败场景上报为 issue

### 文档结构更新

- 目录：`docs/qa/` → `docs/uat/`
- 流程文档：`docs/uat/flows/<module>.md`
- 报告：`docs/uat/reports/YYYY-MM-DD-<module>.md`
- 截图：`docs/uat/screenshots/`

### 测试编写

1. **表单字段**: 添加 `data-testid` 属性（供自动化定位）
   - 参考 `docs/uat/testid-convention.md`（`/uat:init` 自动生成）
   - 命名约定：`<功能域>-<元素类型>`（customer-name-input、submit-button）

2. **下拉/级联选择**: 触发器与浮层选项分离写法
   ```
   步骤 N: 点击触发器 [data-testid="xxx"]
           等待信号：浮层出现（.ant-select-dropdown 可见）
   步骤 N+1: 在浮层中点击「选项文字」
            等待信号：浮层消失
   ```
   - 级联选择每层单独一步
   - 分层等待（下层列表加载完才操作下层）

3. **表单边界测试**: 编写时自动引导补充
   - `/uat:new` 检测有无表单操作，自动询问是否补充边界测试
   - 模板中按 `字段清单 + 测试矩阵` 格式，逐行执行每个测试用例

4. **新增场景**: 测试完成后自动清理
   - 在 flow 文档中指定删除按钮选择器 + 确认弹窗选择器
   - 执行器自动通过 UI 删除测试数据（无法清理时仅警告）

### 失败后上报

- 测试完成若有 ❌ FAIL，终端自动打印上报命令
- GitHub: `gh issue create --title "[BUG] ..."`
- Gitea: `tea issue create ...` 或 `/uat:bug`（自动提取失败场景）

## 关键改进总结

| 方向 | 变化 |
|------|------|
| 命名 | QA → UAT，准确反映功能定位 |
| 测试策略 | API + UI → 纯 UI（聚焦验收层） |
| 机器可执行性 | 选择器、等待信号、已知结论，避免固定 sleep |
| 浮层操作 | 触发器与浮层分离、分层等待、重试机制 |
| 数据生命周期 | 新增场景自动清理，编辑场景保留数据 |
| 错误截图 | 仅失败时截图，减少产物体积 |
