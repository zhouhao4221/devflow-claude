# v5.0.0 (2026-09-18)

> 版本范围：v4.2.0..HEAD（#92 #93）

## 破坏性变更

- **审查类命令按模型档位重组**（REQ-007 #92）：一条命令只能钉一档模型，原 `/rd:pr` 为了 `review` / `comments` 两个子命令整条留在省略档，原 `/rd:review` 需求评审又被钉在 haiku 只能做完整性打勾。三条命令按推理强度重新切分：

  | 命令 | 档位 | 职责 |
  |------|------|------|
  | `/rd:req-review [REQ-XXX] [pass\|reject]` | 省略 | 需求评审（原 `/rd:review`）。提审时新增 **AI 预审**：合理性 / 粒度 / 冲突 / 风险四维度，阻塞 / 建议 / 信息三级，有阻塞时询问是否仍提审，意见以「AI 预审」一行写入评审记录 |
  | `/rd:review [PR-ID] [--level] [--auto]` | 省略 | AI 代码审查（原 `/rd:pr review`，规则原样迁入）；新增 `/rd:review comments` 按人工审查评论改代码 |
  | `/rd:pr [status\|comments\|merge]` | haiku | PR 的 CLI 操作。`comments` 收窄为只读：拉取、过滤、分组展示，末尾提示 `/rd:review comments` |

  **迁移**：
  - `/rd:review REQ-XXX [pass|reject]` → `/rd:req-review REQ-XXX [pass|reject]`
  - `/rd:pr review` → `/rd:review`
  - `/rd:pr comments` 保留，但不再改代码；要按评论改用 `/rd:review comments`
  - 两条守卫只提示不执行：`/rd:review … pass|reject` 提示改用 `/rd:req-review`，`/rd:pr review` 提示改用 `/rd:review`
  - `/rd:migrate` 2C 新增上述映射；旧 `/req:review-pr review` 现映射到 `/rd:review`
  - 自然语言：「评审 + 需求编号」走 `/rd:req-review`，「审 + PR」走 `/rd:review`，「看看 PR 评论」走 `/rd:pr comments`，「按评论改」走 `/rd:review comments`
