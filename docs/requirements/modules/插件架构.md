# 插件架构

## 概述

插件架构模块负责 DevFlow 工具集自身的**分发与维护机制**——即 5 个插件（req/api/pm/diag/uat）的命令、技能、脚本、钩子如何组织、生成与保持一致，而非任一插件的业务功能。

模块核心关注点：

- **单一入口**：每个能力只以 `commands/<name>.md` 一种形态分发。Claude Code 2.x 把插件 skill 也暴露成 `/<plugin>:<skill>`，同名镜像会让斜杠菜单里每条命令重复两遍，故禁止。
- **skills/ 的定位**：只放与命令不同名的手写 helper skill，靠 `description` 在命令运行时自动激活。
- **维护心智模型**：命令/技能是「给 Claude 的指令文档」，脚本只做确定性副作用。

## 关键文件

- `plugins/<plugin>/commands/*.md` — 命令权威源（只能放真命令：需 frontmatter + `description`）
- `plugins/<plugin>/skills/<name>/SKILL.md` — 手写 helper skill（不与命令同名）
- `plugins/<plugin>/shared/*.md` — 命令共享参考文档（`_*.md`、`*-rationale.md`），不注册为命令
- `scripts/check-layout.py` — 布局守卫（`--check` 报错，无参清理）
- `CLAUDE.md` — 「命令与技能结构」维护规范
