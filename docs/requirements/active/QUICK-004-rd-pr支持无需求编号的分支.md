## 问题描述

### 现象
在分支名不含 `REQ-XXX` / `QUICK-XXX` 的分支（如 `fix/index-req001-status`）上执行 `/rd:pr`，创建流程步骤 1 提示「请指定需求编号：/rd:pr REQ-XXX」后直接退出，无法创建 PR。

受影响入口：`/rd:do` 结束时建议执行 `/rd:pr`，而它创建的分支本就不带需求编号；`/rd:commit` 未命中需求时会自动生成无编号分支；手工创建的文档修复分支。`/rd:fix --auto` 不受影响（4.5.2 自带 PR 标题与正文）。REQ-005 补测验收项 2 时发现，该逻辑自 v3 的 `pr.md` 即存在，非 REQ-005 引入。

### 期望
无需求编号的功能分支可以直接 `/rd:pr` 创建 PR：标题与正文从 git 记录生成；只有在主分支（`mainBranch` / `developBranch`）上执行时才提示退出。

---

## 实现方案

### 问题分析
`pr.md`「执行流程（创建 PR）」步骤 1 把「未指定编号且分支名无编号」视为错误直接退出；步骤 4 的标题模板（`feat(REQ-XXX)` / `fix(QUICK-XXX)`）与 Body 模板（需求、功能清单、文件改动清单）全部依赖需求文档，无需求时没有取值来源。

### 解决方案
1. **步骤 1**：拿不到需求编号时——当前分支是 `mainBranch` / `developBranch` → 提示「请先切到功能分支，或指定需求编号」后退出；否则进入**无需求模式**继续后续步骤，不读需求文档。
2. **步骤 4 标题**（`--title` 仍最优先）：无需求模式下 `<base>...HEAD` 只有 1 个提交 → 直接用该提交标题；多个提交 → `<type>: <分支 slug，连字符转空格>`，type 按分支前缀映射（`fix/` → fix、`feat/` → feat、`hotfix/` → hotfix、`docs/` → docs、其他 → chore）。
3. **步骤 4 Body**：无需求模式为「## 提交」（`<base>..HEAD` 的提交标题清单）+「## 变更统计」（`git diff --stat` 汇总行）；分支名含 `-iN` 后缀时正文末尾追加 `closes #N`。
4. 步骤 5–8 与成功输出不变（仍提示 `/rd:pr review`）。
