# 公共逻辑参考 - 执行后验证

> 供 `/rd:do`、`/rd:fix` 在代码改完后、完成提示前执行；「自主验收」一节同时供 `/rd:test` 步骤 7 使用。四条原则：**验证顺序固定、结果必报、无覆盖显式说出、失败修复有上限**。
>
> 同伴文档（同目录，按需 Read；此处不用链接，避免把整组共享文件拖进上下文）：`_delegate.md`（test-runner / impl-worker 委派规则）；agent 定义 `agents/ui-verifier.md`（自主验收的输入与返回格式）。

## 前置：方案里的验收行

方案的每个改动单元附一行「验收」，二选一：

- **可执行命令**：来自 `docs/prompt/testing.md`「必备输入」的测试命令、或 `docs/prompt/architecture.md` 的构建 / lint 命令，已按本单元拼好过滤参数
- **可观察行为**：一句话，写清输入与预期输出（用于没有自动化手段的单元）

验收行同时就是 `_delegate.md`「委派实施」准入第四条「有验收手段」的凭据：**没有可执行命令做验收的单元不能派 `impl-worker`**，主会话自己改。

重构 / 优化 / 升级 / 规范类改动，方案还要附一行「行为变化：无」或列出有意改变的行为；这决定后面测试失败时能不能改断言。

## 验证顺序（固定）

任一级缺少配置就跳过，并在验证结果里写「未配置」，不得静默省略。

1. **编译 / lint**：命令取自 `testing.md`「必备输入」或 `architecture.md`；主会话直接执行。失败先修再往下。
2. **相关测试回归**：按改动文件定位对应测试文件——优先 `testing.md` 里的文件位置 / 命名规则，没有规则时按同名 / 同目录的语言惯例找。派 `test-runner`，prompt 自包含（工作目录、拼好的命令、本次要跑的测试文件清单、返回格式）；测试日志不进主会话。
3. **覆盖判断**：改动文件没有任何对应测试时，按意图类型分流：
   - **小功能 / 修复**：询问用户是否补 UT；同意则按 `test_new.md` 的 `--type=ut --files=<改动文件>` 无文档模式生成，回跑一次。
   - **优化 / 重构 / 升级 / 规范**（目标是行为不变）：不强行补测试。记为「无测试覆盖」，并从方案的改动点派生**手动验证清单**：每条对应一个改动点的可观察行为，写成可勾选项。

   派生出的清单（以及小功能 / 修复里无法补 UT 的 UI 行为）先按下节「自主验收」处理，只有剩下的才进完成提示交给用户。

## 自主验收（UI 可观察项）

用 headless 探针代替「人打开浏览器看一眼」。截图只在 `ui-verifier` 里读，主会话每项只收一段结论。

**前置三条**（缺任一条 → 所有 UI 项留给用户，结果段写「自主验收：未配置（<缺哪条>）」，不得静默跳过）：

1. `docs/prompt/testing.md` 写了 E2E 运行命令（headless）与前端地址
2. 前端可达：主会话按 testing.md 启动并探活（同 `/rd:test` 阶段三）；起不来算未配置
3. E2E 框架是 Playwright（Cypress 等暂不支持）

**分类**（主会话逐项判断，一项一行）：

| 类 | 判断 | 处理 |
|----|------|------|
| `script` | 有入口 + 操作 + 可查询的预期（文本 / 元素 / URL / 提示） | 派 `ui-verifier` |
| `visual` | 预期是样式 / 布局 / 图表 / 动画 | 派 `ui-verifier`，agent 截图后判读 |
| `manual` | 需真实第三方（支付 / 短信 / 邮件）、硬件、多人协作、生产数据，或没有可观察结果 | 留给用户 |

非 UI 的可执行验证（调 HTTP 接口、跑 CLI）主会话直接跑，不派 agent。

**派发**：一项一个 `ui-verifier`，同一页面的 ≤3 项合并成一个；互不相关的项一批并行。prompt 内联 agent 定义列出的全部输入：登录配方只给步骤与 env 变量名——变量值必须在 agent 的 Bash 里可用：要么启动 Claude Code 前已 export，要么 testing.md 的 E2E 命令自己加载 `.env.test`（不入 git），两者都没有时对应项 BLOCKED；探针目录 REQ / QUICK 用编号，do / fix 用当前分支 slug（无分支用 `adhoc-<YYYYMMDD>`）；产物目录取 testing.md，缺省 `test-results/acceptance/`；候选前端文件取自改动清单，≤5 个。

**主会话纪律**：不 Read 任何 png / aria 产物；FAIL 项把证据与产物路径交给用户自己看；不因 FAIL 重派（agent 已自修过一次）；BLOCKED 原因是 testing.md 缺项时提示补哪一项。

**回写**（需求文档验证章节 / 验证结果段的「手动验证」条目）：

- PASS → `- [x] <原文>（自动验收：<探针路径>）`
- FAIL、BLOCKED → 保持裸 `- [ ] <原文>`，失败清单 / 报告写期望 vs 实际或阻塞原因
- `manual` → 逐项请用户验证：通过则勾选；**用户明确选择暂缓**才标 `（未实测：<原因>）`；都没有就保持裸 `- [ ]`

AI 不自动打「未实测 / 待观察」标注：带标注的未勾项会被 `/rd:done` 放行，暂缓只能由人决定。探针默认保留并列入「修改文件」，下次 `/rd:test` 阶段三当回归跑；是否提交由用户在 commit 时定。readonly 仓库不写需求文档，只在报告里列出。

## 失败处理

- 测试失败 → 修代码 → 重跑，**最多 2 轮**。仍失败则停下，把 `test-runner` 返回的失败清单原样交给用户，不进入完成提示。
- **红线：不得为了让测试通过而修改断言、期望值、跳过或删除用例。** 唯一例外是方案的「行为变化」行已声明该行为改变且用户已确认；此时改测试要在验证结果的「测试改动」里逐条列出原因。
- `test-runner` 回 `ERROR`（依赖缺失、命令不存在、编译失败）→ 报告原因并询问用户，不改命令、不换框架绕过。

## 验证结果段

放在完成提示中，与「修改文件」并列。缺项写「未配置」或「无」，不得省略整段。

```
验证结果：
- 编译：✓ | ✗ | 未配置
- lint：✓ | ✗ | 未配置
- 测试：<通过数>/<总数> 通过（<命令>） | 未配置
- 无测试覆盖：<文件列表> | 无
- 自主验收：<PASS 数>/<派发项数>（FAIL n，BLOCKED n） | 未配置（<原因>） | 无 UI 项
- 手动验证：
  - [ ] <改动点对应的可观察行为>
- 测试改动：<改了哪个用例、原因> | 无
```

后续 `/rd:commit` 不重跑验证，直接采信这段；`/rd:review` 审查时可对照它检查覆盖缺口。
