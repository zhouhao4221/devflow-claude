# QA 执行引导

仅在 `/qa:run` 命令执行时激活。

**核心原则**：Claude 是指挥家，不直接实现操作细节——根据 flow 文档的 `操作方式` 字段决定调用哪个工具，工具负责实际执行。

---

## 一、执行前准备

### 1. 读取 flow 文档

```
docs/qa/flows/<module>.md
```

解析以下字段：
- `操作方式`：决定使用哪个工具
- `入口`：初始 URL 或路径
- `测试数据`：全局复用数据，执行时按字段名注入
- `已知结论`：跳过列表，对应场景标记 SKIP
- 所有 `S0N` 场景：步骤列表 + 等待信号 + 预期结果

### 2. 工具选择规则

| 操作方式 | 使用工具 | 说明 |
|---------|---------|------|
| browser | `browser:browser` skill | 需要 Codex Chrome 或 Claude 桌面端 |
| api | Bash curl / 内置 HTTP | 直接调用接口 |
| api-then-verify | Bash curl（造数）→ `browser:browser`（回查） | 先 API 建数据，再浏览器验证 |
| desktop | 提示用户手动操作 | 当前不支持自动化 |

**环境检测**：若操作方式为 `browser` / `api-then-verify` 但当前环境无浏览器工具，输出：
```
⚠️  当前环境不支持浏览器自动化
💡  请在 Codex Chrome 或 Claude 桌面客户端中运行 /qa:run
```
然后终止。

## 二、逐场景执行

### 执行前：处理已知结论

读取 `已知结论` 区块，对命中的场景直接标记 **SKIP**，不执行，跳到下一个场景：

```
⏭ S02 <场景名> — SKIP（已知结论：手工新增接口返回 500）
```

### 对每个场景 `S0N`，按以下流程执行：

```
1. 输出场景标题：▶ S01 <场景名称>
2. 数据准备：若有 "数据准备" 字段，先执行（API / 脚本 / 提示手动）
3. 检查前置条件是否满足
4. 逐步执行操作步骤（使用步骤中的选择器 + 等待信号）
5. 执行完所有步骤后，逐条验证预期结果
6. 记录结果：✅ PASS 或 ❌ FAIL（附失败原因）
```

---

## 三、选择器使用规则（browser 模式）

**优先级**（高到低）：

1. `[data-testid="xxx"]` — 测试专用属性，最稳定
2. `[aria-label="xxx"]` — 无障碍属性，较稳定
3. 具体 CSS 类（`.ant-btn-primary`）— 组件库专有，可接受
4. 通用标签组合（`button > span`）— 最后手段，易碎

若 flow 文档未提供选择器，先尝试在页面找 `data-testid`，再降级。**不抓全页 DOM**，只读取目标容器（如 `.ant-modal`、表格容器、搜索区域）。

---

## 四、等待信号策略（替代固定 sleep）

按 flow 文档步骤中的 `等待信号` 字段执行，无字段时使用默认策略：

| 信号类型 | 触发条件 | 默认超时 |
|---------|---------|---------|
| 文字出现 | DOM 中出现指定文字 | 10s |
| 元素出现 | 指定选择器可查到 | 10s |
| 元素消失 | loading/spinner 消失 | 15s |
| URL 变化 | 当前 URL 匹配目标 | 10s |
| 无信号字段 | 等待网络空闲（200ms 内无新请求） | 5s |

**禁止** 使用无条件 `sleep N秒`，除非场景备注明确说明原因。

---

## 五、api-then-verify 执行模式

场景操作方式为 `api-then-verify` 时：

1. **造数阶段**（Bash curl）：
   - 调用 flow 文档 `数据准备` 字段中的接口
   - 记录返回的资源 ID / 关键字段，供后续步骤引用
   - 若接口返回非 2xx：标记该场景为 ❌ FAIL，附错误信息，继续下一个场景

2. **回查阶段**（browser）：
   - 导航到入口 URL
   - 验证页面展示与 API 返回一致
   - 只抓取目标容器（如列表区域），不截取全页

## 六、断言策略

| 断言类型 | 验证方式 |
|---------|---------|
| 文字出现 | 在目标容器中搜索指定文本 |
| 元素存在 | 在目标容器查找指定选择器 |
| 元素不存在 | 确认选择器在容器内查无结果 |
| URL 匹配 | 检查当前页面 URL |

**截图策略**：**仅在步骤失败时截图**，不对通过的步骤截图。截图路径：`docs/qa/screenshots/YYYY-MM-DD-S0N-<step>.png`

---

## 七、表单边界 & 字符类型测试执行策略

当场景标题含「边界」或「字符」关键词，或场景中有 `测试矩阵` 表格时，按如下规则逐行执行：

```
对 测试矩阵 中的每一行（B1-B3 边界、C1-C7 字符）：
  1. 清空目标字段（Ctrl+A → Delete）
  2. 输入当前行的测试值
  3. 点击提交按钮，等待反馈信号
  4. 断言实际结果是否符合预期列：
     - 边界行（B*）：预期出现内联错误提示，不触发接口
     - 字符行（C*）：合法字符保存后，详情页展示不乱码、不执行脚本
  5. 任一行实际 ≠ 预期 → 整行记为 ❌ FAIL，截图，附失败行编号和实际结果
  6. 全部通过 → 场景标记 ✅ PASS
```

**输入前清场**：每行测试前必须清空字段，避免上一行残值干扰。

**XSS 验证补充**：C4（XSS）场景保存成功后，在详情/列表页重新加载并检查：
- 浏览器开发者工具 Console 无 alert 弹出
- 字段展示为纯文本 `<script>alert(1)</script>`，而非执行脚本

## 八、结果输出格式

### 终端汇总

```
═══════════════════════════════════
  QA 执行报告：<module>
  执行时间：YYYY-MM-DD HH:mm
═══════════════════════════════════
  ✅ S01 正常登录           PASS
  ❌ S02 密码错误提示        FAIL  表单未显示错误信息
  ⏭ S03 手工新增           SKIP  已知结论：接口 500
  ✅ S04 退出登录           PASS
  ❌ S05 表单边界 & 字符     FAIL  C4(XSS) 未转义，B2(超长) 未拦截
───────────────────────────────────
  通过：2   失败：2   跳过：1   共 5
═══════════════════════════════════
```

### 报告文件格式

写入 `docs/qa/reports/YYYY-MM-DD-<module>.md`：

```markdown
# QA 报告：<module>

执行时间：YYYY-MM-DD HH:mm
操作方式：browser

## 汇总

| 场景 | 名称 | 结果 | 备注 |
|------|------|------|------|
| S01 | 正常登录 | ✅ PASS | - |
| S02 | 密码错误提示 | ❌ FAIL | 表单未显示错误信息 |
| S03 | 手工新增 | ⏭ SKIP | 已知结论：接口 500 |
| S05 | 表单边界 & 字符 | ❌ FAIL | C4(XSS)未转义；B2(超长)未拦截 |

通过：2 · 失败：2 · 跳过：1

## 失败详情

### S02 密码错误提示
- **失败步骤**：步骤 3 - 点击登录后
- **预期**：页面显示「密码错误」提示
- **实际**：页面无任何提示，直接刷新
- **截图**：docs/qa/screenshots/2026-05-12-S02-step3.png

### S05 表单边界 & 字符 — 失败行
| 行 | 输入 | 预期 | 实际 |
|----|------|------|------|
| B2 | 超长字符串（51位） | 提示超限 | 正常提交，数据被截断存储 |
| C4 | `<script>alert(1)</script>` | 展示为文本 | 页面弹出 alert 弹窗 |
- **截图**：docs/qa/screenshots/2026-05-12-S05-B2.png、S05-C4.png
```

更新 flow 文档元信息的 `最后执行` 字段为当前日期。

### 有 FAIL 时的后续提示

当报告中存在 ❌ FAIL 场景时，在终端输出最终提示：

```
⚠️  发现 <N> 个失败场景，建议上报为缺陷工单：

💡 GitHub Issue:
   gh issue create --title "[BUG] <module> - <简短描述>" \
     --body "$(cat docs/qa/reports/YYYY-MM-DD-<module>.md)" \
     --label bug

💡 Gitea Issue:
   tea issue create --title "[BUG] <module> - <简短描述>" \
     --description "$(cat docs/qa/reports/YYYY-MM-DD-<module>.md)"

   或通过 /req:issue new 创建，自动关联需求。

📎 截图路径：docs/qa/screenshots/YYYY-MM-DD-*
   上报 Issue 时建议手动附上截图附件。
```
