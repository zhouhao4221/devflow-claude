# QA 执行引导

仅在 `/qa:run` 命令执行时激活。

**核心原则**：Claude 是指挥家，不直接实现操作细节——根据 flow 文档的 `操作方式` 字段决定调用哪个工具，工具负责实际执行。

---

## 一、执行前准备

### 1. 读取 flow 文档

```
docs/qa/flows/<module>.md
```

解析以下字段：
- `操作方式`：决定使用哪个工具
- `入口`：初始 URL 或路径
- 所有 `S0N` 场景：步骤列表 + 预期结果

### 2. 工具选择规则

| 操作方式 | 使用工具 | 说明 |
|---------|---------|------|
| browser | `browser:browser` skill | 需要 Codex Chrome 或 Claude 桌面端 |
| api | Bash curl / 内置 HTTP | 直接调用接口 |
| desktop | 提示用户手动操作 | 当前不支持自动化 |

**环境检测**：若操作方式为 `browser` 但当前环境无浏览器工具，输出：
```
⚠️  当前环境不支持浏览器自动化
💡  请在 Codex Chrome 或 Claude 桌面客户端中运行 /qa:run
```
然后终止。

---

## 二、逐场景执行

对每个场景 `S0N`，按以下流程执行：

### 执行流程

```
1. 输出场景标题：▶ S01 <场景名称>
2. 检查前置条件是否满足（若需要特定状态，先导航/初始化）
3. 逐步执行操作步骤
4. 执行完所有步骤后，逐条验证预期结果
5. 记录结果：✅ PASS 或 ❌ FAIL（附失败原因）
```

### 断言策略（browser 模式）

| 断言类型 | 验证方式 |
|---------|---------|
| URL 变化 | 检查当前页面 URL |
| 文字出现 | 在 DOM 中搜索指定文本 |
| 元素存在 | 查找指定选择器 |
| 元素不存在 | 确认选择器查无结果 |
| 截图留证 | 关键步骤截图，路径记录到结果 |

### 失败处理

- 某步骤执行失败 → 记录失败原因，**继续下一个场景**（不中断整体）
- 截图路径写入结果：`docs/qa/screenshots/YYYY-MM-DD-S0N.png`

---

## 三、结果输出格式

所有场景执行完毕后，输出汇总并写入报告文件。

### 终端汇总

```
═══════════════════════════════════
  QA 执行报告：<module>
  执行时间：YYYY-MM-DD HH:mm
═══════════════════════════════════
  ✅ S01 正常登录           PASS
  ❌ S02 密码错误提示        FAIL  表单未显示错误信息
  ✅ S03 退出登录           PASS
───────────────────────────────────
  通过：2/3   失败：1/3
═══════════════════════════════════
```

### 报告文件格式

写入 `docs/qa/reports/YYYY-MM-DD-<module>.md`：

```markdown
# QA 报告：<module>

执行时间：YYYY-MM-DD HH:mm
操作方式：browser

## 汇总

| 场景 | 名称 | 结果 | 备注 |
|------|------|------|------|
| S01 | 正常登录 | ✅ PASS | - |
| S02 | 密码错误提示 | ❌ FAIL | 表单未显示错误信息 |

通过：2/3 · 失败：1/3

## 失败详情

### S02 密码错误提示
- **失败步骤**：步骤 3 - 点击登录后
- **预期**：页面显示「密码错误」提示
- **实际**：页面无任何提示，直接刷新
- **截图**：docs/qa/screenshots/2026-05-12-S02.png
```

更新 flow 文档元信息的 `最后执行` 字段为当前日期。
