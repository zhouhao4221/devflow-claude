# 创建测试流程文档

通过多轮对话收集测试场景，生成结构化的 flow 文档。

## 命令格式

```
/qa:new [module]
```

---

## 执行流程

### 1. 确定模块名

- 若参数已传入模块名，直接使用
- 否则询问：`请输入测试模块名称（如：用户登录、商品搜索）`

检查 `docs/qa/flows/<module>.md` 是否已存在：
- 已存在 → 提示 `该模块已有测试文档，是否覆盖？(y/n)`
- 不存在 → 继续

### 2. 读取模板

读取 `plugins/qa/templates/flow-template.md`，了解 flow 文档结构。

### 3. 多轮对话收集信息

**阶段一：收集基本信息**

依次询问：
1. 操作方式：`browser / api / api-then-verify / desktop`（默认 browser）
2. 入口 URL 或路径

**阶段二：收集全局信息**

询问：
1. 是否有全局测试数据？（账号、密码、通用字段值等）整理为 `测试数据` 表格。
2. 是否有已知不通过 / 可跳过的路径？（如"接口已知返回 500 跳过"）整理为 `已知结论` 列表。

**阶段三：逐轮收集测试场景**

每轮询问：
```
请描述一个测试场景（输入"完成"结束）：
- 场景名称？
- 前置条件？（用户状态、页面状态等）
- 场景类型？（新增 / 编辑 / 查询 / 删除 / 其他）
- 是否需要数据准备？（api / 脚本 / 手动 / 已有数据）
- 若为「新增」场景：清理测试数据的方式是什么？（DELETE 接口路径 / UI 删除按钮 testid / 无法自动清理）
- 操作步骤？（逐步描述，尽量说明点击的是哪个按钮/输入框）
- 关键元素的 data-testid？（不知道填"待补充"）
- 步骤中是否涉及下拉 / 级联选择（Select / Cascader / 省市区）？
  - 有 → 触发器 testid 是什么？是普通下拉还是级联（省→市→区）？是否支持搜索？
  - AI 自动生成「触发器点击 + 浮层等待 + 选项点击」分离写法，级联每层单独一步
- 每个关键步骤的等待信号？（等什么出现/消失/URL 变化才算完成）
- 预期结果？（可观测的断言）
```

AI 将用户的自然语言整理为标准格式，`选择器` 字段填入步骤行内，`等待信号` 填在步骤下方缩进行。每收集完一个场景展示整理结果，询问 `是否继续添加场景？`。

**用户说"完成"后**进入阶段四。

**阶段四：表单边界 & 字符类型检测（自动触发）**

分析已收集的场景，判断是否包含「输入框 / 表单提交」步骤：

- **有表单输入** → 主动询问：
  ```
  检测到场景中有表单操作，建议补充「表单边界 & 字符类型」测试场景（覆盖空值、超长、特殊字符、XSS 等）。
  是否添加？(y/n)
  ```
  - `y` → 逐字段引导：
    1. 哪些字段需要测试？（逐一列出）
    2. 每个字段的：最大/最小长度限制是多少？是否有字符类型约束（仅数字/仅中文等）？
    3. 对空值/超长/特殊字符的预期行为是什么？（内联提示文字 / 截断 / 其他）
    4. 按模板 `SXX 表单边界 & 字符类型` 生成对应场景，自动填充字段清单和字段约束
  - `n` → 跳过，提示 `💡 后续可手动编辑 flow 文档添加边界测试场景`

- **无表单输入** → 跳过此阶段

### 4. 生成文档

严格按模板格式生成 `docs/qa/flows/<module>.md`：
- 创建 `docs/qa/flows/` 目录（如不存在）
- 场景 ID 按 S01、S02... 顺序编号
- `测试数据` 和 `已知结论` 区块必须写入（无内容时保留空占位符）

### 5. 输出

```
✅ 测试流程文档已创建

📁 docs/qa/flows/<module>.md
🎯 场景数：3

💡 /qa:run <module>   立即执行测试
💡 直接编辑：docs/qa/flows/<module>.md
```
