# 创建测试流程文档

通过多轮对话收集测试场景，生成结构化的 flow 文档。

## 命令格式

```
/qa:new [module]
```

---

## 执行流程

### 1. 确定模块名

- 若参数已传入模块名，直接使用
- 否则询问：`请输入测试模块名称（如：用户登录、商品搜索）`

检查 `docs/qa/flows/<module>.md` 是否已存在：
- 已存在 → 提示 `该模块已有测试文档，是否覆盖？(y/n)`
- 不存在 → 继续

### 2. 读取模板

读取 `plugins/qa/templates/flow-template.md`，了解 flow 文档结构。

### 3. 多轮对话收集信息

**阶段一：收集基本信息**

依次询问：
1. 操作方式：`browser / api / desktop`（默认 browser）
2. 入口 URL 或路径

**阶段二：收集测试场景**

逐轮收集场景，每轮询问：
```
请描述一个测试场景（输入"完成"结束）：
- 场景名称？
- 前置条件？（用户状态、页面状态等）
- 操作步骤？（逐步描述）
- 预期结果？（可观测的断言）
```

AI 将用户的自然语言整理为标准格式。每收集完一个场景展示整理结果，询问 `是否继续添加场景？`。

**用户说"完成"后**进入阶段三。

### 4. 生成文档

严格按模板格式生成 `docs/qa/flows/<module>.md`：
- 创建 `docs/qa/flows/` 目录（如不存在）
- 场景 ID 按 S01、S02... 顺序编号

### 5. 输出

```
✅ 测试流程文档已创建

📁 docs/qa/flows/<module>.md
🎯 场景数：3

💡 /qa:run <module>   立即执行测试
💡 /qa:edit <module>  手动编辑文档
```
